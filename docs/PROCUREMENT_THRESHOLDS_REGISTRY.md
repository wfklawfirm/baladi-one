# سجل سقوف الشراء العام — الهيكل والمحتوى الحالي وآلية التحميل

التاريخ: 2026-11-27 · المصادر: ترحيلات 0024 و0040 و0041، `lib/procurement.ts`، `components/procurement/Wizard.tsx`، `app/staff/projects/procurement/thresholds/page.tsx` و`actions.ts`. تحقق حيّ (SELECT فقط، مشروع sdpemqqozovxmoaerspq): `procurement_threshold` = **0 صف**، العمود `threshold_kind` موجود، `procurement_legal_source` = 17 صفًّا (كلها `pending_review`)، `procurement_provision` = 0.

> لا يحوي هذا المستند أي رقم سقف. كل قيمة سقف أو نسبة أو مهلة: **غير متحقق منه / يتطلب مراجعة قانونية**. لا بند مصنَّف «Legally Verified & Approved».

## 1) الأنواع الأربعة (قيد `procurement_threshold_kind_chk`)

لا يجوز خلطها (نص تعليق 0040). التعريف أدناه إجرائي من بنية الجدول؛ **المضمون القانوني لكل نوع غير متحقق منه**.

| النوع | الرمز | ما يضبطه (حسب التصميم) | ما يستعمله اليوم |
|---|---|---|---|
| سقف الطريقة | `method` | نطاق قيمة لأسلوب شراء؛ حقل `method` إلزامي لهذا النوع فقط | الموصي `recommendMethod` (ولا شيء غيره) |
| الاختصاص | `competence` | الجهة المختصة بالقرار حسب القيمة (حقل `applies_to` نص حر) | لا شيء: لا محرك ولا واجهة |
| التصديق الإداري | `admin_approval` | جهة التصديق حسب القيمة (`applies_to`) | لا شيء |
| الرقابة المالية | `financial_control` | الرقابة المالية/المسبقة حسب القيمة (`applies_to`) | لا شيء |

## 2) هيكل الجدول `procurement_threshold`

| العمود | الوصف |
|---|---|
| `municipality_id` | البلدية (الصف خاص بها) |
| `threshold_kind` | أحد الأنواع الأربعة، افتراضي `method` |
| `method` | أحد الأساليب السبعة؛ يقبل NULL لغير نوع `method` |
| `min_value`, `max_value`, `currency` | الحدّان (الأعلى اختياري) والعملة LBP/USD؛ `max >= min` |
| `comparison_operator` | `between_inclusive` (افتراضي)، `lt`, `lte`, `gt`, `gte`, `eq` |
| `effective_from`, `effective_to` | فترة السريان |
| `source` | نص المصدر، إلزامي وغير فارغ |
| `legal_source_id`, `provision_id` | ربط اختياري بـ `procurement_legal_source` و`procurement_provision` |
| `applies_to`, `conditions`, `exceptions` | نصوص حرة تُملأ عند المراجعة |
| `review_status` | `pending_review` (افتراضي)، `verified`, `rejected`, `superseded` |
| `reviewed_by`, `last_reviewed_at` | المراجع وتاريخ المراجعة |
| `created_by`, `created_at` | الإدخال |

جداول مساندة: `procurement_legal_source` (نوع الصك، رقمه، تاريخه، رابط رسمي، الجريدة، الجهات المنطبقة، حالة التحقق `pending_review/verified/rejected/superseded/source_unreachable`) و`procurement_provision` (مادة/فقرة، موضوع، النص الأصلي NULL إلى أن يُقرأ من المصدر، استثناءات، حالة تحقق). RLS: قراءة فقط؛ لا سياسة كتابة؛ سجل المصادر قابل للقراءة لأي مستخدم مصادَق في 0040 (يُقترح تضييقه في 0046 المسودة، غير مطبق).

## 3) المحتوى الحالي: فارغ، ولماذا

| الواقعة | السبب (من الملفات) |
|---|---|
| 0 صف سقوف | لا أرقام قانونية في الشيفرة أو الترحيلات عمدًا؛ يُحمَّل كل سقف بمصدره بعد التحقق من النص |
| المرسوم 14063/2024 (تعديل السقوف) | ملف الهيئة يعرض ترويسة الجريدة فقط؛ الحالة: Blocked by Missing Evidence |
| القانون 21/2025 (الاختصاص والتصديق) | تعرضه الهيئة كجدول توضيحي؛ النص الرسمي لم يُراجَع |
| القانون 244/2021 | تاريخ صدور متعارض (2021-07-19 مقابل 2023-07-18)؛ النسخة المجمّعة (تشرين الأول 2024) لم تُقرأ |
| 17 مصدرًا في `procurement_legal_source` | بيانات وصفية فقط (مضيف PPA)، كلها `pending_review`، بلا نص مواد |
| `procurement_setting.art29_limit_pct` | NULL حتى تحميل قيمة بمصدر |

## 4) سير العمل لتحميل قيمة (المصدر / الحكم / المراجعة)

الحالة الفعلية للأدوات، وما ينقص:

| الخطوة | ما هو متاح اليوم | الفجوة |
|---|---|---|
| 1. الحصول على النص الرسمي | يدوي خارج النظام | لا آلية؛ النص الأصلي لا يُحمَّل قبل قراءته من المصدر الرسمي |
| 2. تسجيل المصدر | صف في `procurement_legal_source` (محمّل بـ 0041) | لا RPC لإضافة/تعديل مصدر (تعليق 0040: «تُضاف مع شاشة المراجعة») |
| 3. تسجيل الحكم (مادة/فقرة) | الجدول `procurement_provision` موجود | لا RPC ولا واجهة؛ 0 صف |
| 4. إدخال السقف | `procurement_threshold_add(p_method, p_min, p_max, p_currency, p_from, p_to, p_source)`؛ المصدر إلزامي (`source_required`)؛ يبدأ `pending_review`؛ يُدقَّق في `audit_event` | **الدالة لا تقبل** `threshold_kind` ولا `legal_source_id` ولا `provision_id` ولا `comparison_operator` ولا `applies_to`؛ و`p_method` إلزامي؛ فلا يمكن عبر الواجهة تحميل سقف اختصاص/تصديق/رقابة؛ والصف الناتج دائمًا نوع `method` |
| 5. المراجعة | `procurement_threshold_set_review(p_id, p_status, p_effective_to)` تغيّر الحالة وتاريخ الانتهاء وتُدقَّق | لا تكتب `reviewed_by` ولا `last_reviewed_at`؛ لا فصل بين المُدخِل والمراجع (لا مبدأ العينين، بخلاف `review_service_version`)؛ لا شرط وجود `legal_source_id` قبل `verified` |
| 6. السريان | `effective_from/to`؛ الموصي يتجاهل `rejected` و`superseded` ويأخذ `pending_review` و`verified` | يُعامل `pending_review` كسقف نافذ مع وسم «السقف بانتظار المراجعة القانونية»؛ قرار سياسة غير متحقق منه |

التوصية الإجرائية (لا تغيّر الشيفرة هنا): قبل تحميل أي سقف يلزم نص رسمي مقروء، وتسجيل المصدر والحكم، ثم إدخال القيمة بمصدرها، ثم مراجعة قانونية مستقلة عن المُدخِل، ولا يُعتمد `verified` إلا بعدها. الأرقام نفسها: **غير متحقق منها / تتطلب مراجعة قانونية**.

## 5) سلوك الموصي عند غياب البيانات (`no_data`)

من `recommendMethod(value, currency, thresholds, today)`:

| الحالة | النتيجة |
|---|---|
| لا سقوف إطلاقًا (القائمة فارغة، وهي الحال الآن) | `status: "no_data"` ورسالة «بيانات غير متوفرة: حمّل السقوف النافذة»، بلا أساليب |
| سقوف موجودة لكن لا نافذ بهذه العملة/التاريخ | `no_data` برسالة إضافية «لا سقوف نافذة بهذه العملة في هذا التاريخ» |
| لا سقف يغطي القيمة | `no_match` («لا تغطي السقوف المحمَّلة هذه القيمة») |
| تطابق واحد أو أكثر | `matched`؛ إن تعددت الأساليب: «يلزم تقدير المختص»؛ ويُوسم غير المتحقق «السقف بانتظار المراجعة القانونية» |

سلوك ملازم: الحدّان شاملان؛ لا يمنع شيئًا أبدًا (استرشادي)؛ `methodMismatch` معلوماتي فقط. في معالج الشراء الخطوة 4 تعرض عند `no_data`: «يتطلب تحققًا قانونيًا: لا يعرض النظام طريقة شراء أو اختصاصًا أو تصديقًا قبل تحميل سقوف نافذة متحقَّق منها»، وينشئ بند خطة بلا أسلوب. كشف التجزئة يتجنب حقل `band_changes` حين لا سقوف.

## 6) فجوات مرصودة في السجل

| # | الفجوة | الأثر |
|---|---|---|
| 1 | `Threshold` و`activeThresholds` و`recommendMethod` لا تقرأ `threshold_kind` ولا تفلتر عليه (النوع `Threshold` بلا هذا الحقل) | لو حُمِّل لاحقًا سقف اختصاص/تصديق/رقابة، قد يدخل في حساب توصية الأسلوب؛ يلزم الفصل قبل أي تحميل لنوع غير `method` |
| 2 | صفحة السقوف تعرض أسلوبًا فقط وبلا نوع ولا مصدر قانوني مرتبط | لا إدخال للأنواع الثلاثة الأخرى |
| 3 | `procurement_threshold_set_review` لا تسجّل المراجع | لا أثر على من اعتمد |
| 4 | لا دالة لإدخال المصادر والأحكام ولا شاشة مراجعة | استحالة ربط `legal_source_id`/`provision_id` من التطبيق |
| 5 | نص «10 أيام عمل» ثابت في `lib/procurement.ts` (F-4 في التدقيق الأمني) | رقم قانوني غير متحقق منه في الشيفرة |
| 6 | قبول `pending_review` ضمن الحساب | توصية قد تُبنى على سقف غير مراجَع (موسوم فقط) |
