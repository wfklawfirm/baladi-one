# مصفوفة صلاحيات الشراء العام — الموجود في الشيفرة وRLS، وما لم يُنمذَج

التاريخ: 2026-11-27 · المصادر: ترحيلات 0015 (`_council_muni`) و0024 و0040 و0042–0046، صفحات `app/staff/procurement/**` و`app/staff/projects/procurement/**`، `docs/PERMISSION_MATRIX.md` و`PROCUREMENT_SECURITY_AUDIT.md`. تحقق حيّ (SELECT فقط): على الإنتاج 17 دالة `procurement_*` (0024 و0042)؛ `anon` بلا EXECUTE على الدوال المفحوصة و`authenticated` معه؛ لا جداول 0043–0045 على الإنتاج.

> هذا وصف لما تفعله الشيفرة، **لا** لما يقرره القانون. أي دور أو جهة اختصاص أو تصديق خارج الجدول: **غير متحقق منه / يتطلب مراجعة قانونية**. لا بند مصنَّف «Legally Verified & Approved».

## 1) الأدوار الفعلية

| الاسم | الواقع في قاعدة البيانات |
|---|---|
| anon / مواطن | دور Postgres `anon` (لا حسابات للمواطنين: المواطن = anon) |
| staff (موظف) | `staff_member.role = 'staff'` |
| mayor (رئيس) | `staff_member.role = 'mayor'` |
| admin (مسؤول) | `staff_member.role = 'admin'` |
| تجريبي | علم `is_demo` على صف staff/mayor؛ تُرشَّح القراءة بـ `is_demo or not is_demo_staff()` |

حارس الكتابة لكل دوال الشراء: `_council_muni()` = «للمستدعي صف `mayor` أو `admin`؛ تُؤخذ أقدم عضوية». الاستثناء الوحيد أنه لا ينظر إلى `is_demo` (F-3 معلّق في 0046، غير مطبق).

## 2) مصفوفة الدور × النوع

| الدور | قراءة جداول الشراء (RLS) | كتابة (RPC) | صفحات الشراء |
|---|---|---|---|
| anon / مواطن | لا (السياسات لـ `authenticated`) | لا (`revoke … from public, anon`) | لا |
| مستخدم مصادَق بلا صف staff | لا (`is_staff` تفشل)؛ استثناء: سجلا المصادر والأحكام قراءتهما `using (true)` في 0040 | لا (`forbidden`) | لا |
| staff | نعم لجداول الشراء بنفس البلدية (`is_staff(municipality_id)`)؛ عدا العروض قبل الفتح، ومستندات 0045 وقرارات الخطة (mayor/admin فقط) | **لا** (`_council_muni` ترفضه) | لا (تحويل إلى `/staff`) |
| mayor | نعم لبلديته | **نعم** لكل الدوال | نعم |
| admin | نعم | **نعم** لكل الدوال | نعم |
| رئيس تجريبي (demo mayor) | يقرأ الصفوف التجريبية فقط | نعم، وقد يكتب على بلدية حقيقية مرتبط بها (F-3) | نعم |

ملاحظات: لا فصل بين الرئيس والمسؤول في أي دالة شراء؛ لا دور «وحدة شراء» أو «لجنة» أو «مدقق» (الحالة: Not Implemented في تقرير التنفيذ). الصفحات تحجب غير الرئيس/المسؤول لكن الإنفاذ الفعلي في الخادم (RPC/RLS).

## 3) المصفوفة لكل RPC (كلها SECURITY DEFINER، `search_path` ثابت، `revoke … from public, anon` و`grant … to authenticated`، والحارس `_council_muni()`)

| RPC | الترحيل / حالة التطبيق | الصلاحية الفعلية | قيود ذات صلة |
|---|---|---|---|
| `procurement_plan_add` / `_set_status` / `_link_contract` | 0024 / مطبق | mayor, admin | تدقيق في `audit_event`؛ فحص بلدية بند الموازنة والعقد |
| `procurement_threshold_add` | 0024 / مطبق | mayor, admin | المصدر إلزامي؛ يبدأ `pending_review`؛ بلا نوع السقف |
| `procurement_threshold_set_review` | 0024 / مطبق | mayor, admin | لا فصل بين المُدخِل والمراجع؛ لا تسجيل المراجع |
| `procurement_set_setting` | 0024 / مطبق | mayor, admin | نسبة «المادة 29» تتطلب مصدرًا |
| `procurement_committee_add` / `_member_add` / `_report` | 0024 / مطبق | mayor, admin | النتيجة غير المعلّقة تتطلب تاريخًا؛ تصريح تعارض المصالح للعلم فقط |
| `procurement_publication_add` | 0024 / مطبق | mayor, admin | يتطلب عقدًا أو بند خطة |
| `procurement_stage_set` | 0024 / مطبق | mayor, admin | يعيد الكتابة فوق الدليل دون حفظ السابق في التدقيق (F-1b غير معالج) |
| `contract_link_decision_late` | 0024 / مطبق | mayor, admin | سبب ≥ 15 حرفًا؛ لا استبدال لربط قائم |
| `procurement_complete_contract` | 0024 / مطبق | mayor, admin | تحذير (يتطلب إقرارًا) عند غياب محضر استلام؛ يتحول إلى منع إن اعتُمدت القاعدة `PPL-244-ACCEPT` «verified» (وهي غير متحقق منها الآن) |
| `procurement_supplier_add` | 0042 / مطبق | mayor, admin | — |
| `procurement_set_bids_open` | 0042 / مطبق (التقوية في 0046 غير مطبقة) | mayor, admin | يرفض بعد الفتح أو بموعد ماضٍ؛ تقصير الموعد بعد وجود عروض غير ممنوع إلا في 0046 المسودة (F-1) |
| `procurement_bid_add` | 0042 / مطبق | mayor, admin | يُرفض بعد الفتح (`bids_closed`) |
| `procurement_bid_count` | 0042 / مطبق | mayor, admin | يعمل والعروض مختومة |
| `procurement_bid_evaluate` | 0042 / مطبق | mayor, admin | يُرفض قبل الفتح (`bids_sealed`)؛ يغيّر حقلَي التقييم فقط |
| `procurement_objection_*` (4 دوال) | 0043 / **مسودة غير مطبقة** | mayor, admin | الأثر على الإجراء نص حر؛ لا أثر قانوني محتسب |
| `procurement_file_start/check_set/advance/return/finish/cancel/restart` | 0044 / **مسودة غير مطبقة** | mayor, admin | إتمام المرحلة يتطلب مرجع إثبات؛ الانتقال وفق جدول انتقالات؛ كل المراحل `pending_review` |
| `procurement_document_record`, `procurement_plan_create_decision` | 0045 / **مسودة غير مطبقة** | mayor, admin | القراءة محصورة بـ mayor/admin؛ ربط القرار يرفض بلا قالب مجال «procurement» |

القراءة المباشرة (RLS): جداول الشراء `select` فقط لـ `authenticated` عبر `is_staff(municipality_id)`؛ تمنع 0042 قراءة `procurement_bid` لأي دور قبل `bids_open_on`؛ لا سياسات كتابة، فلا كتابة إلا عبر الدوال؛ سجلات 0044 للتعريفات (`procurement_workflow*`) قراءتها `using (true)` للمصادَقين.

## 4) ما لا يعرفه النظام: جهات الاختصاص والتصديق (لم تُنمذَج)

لا جدول ولا عمود ولا قاعدة لأي جهة أدناه؛ المنمذج دورا `mayor/admin` الإداريان فقط وليسا مفوَّضين قانونيًا بأي قرار شراء في النظام. لا أحد منها **متحقق منه**.

| الجهة / الصفة | ما غير معروف | المطلوب من القانوني |
|---|---|---|
| المجلس البلدي | هل يختص بقرار/موافقة شراء، بأي قيمة وأي أسلوب؟ (النظام يربط قرار مجلس بعقد، دون قاعدة اختصاص) | نص الاختصاص وسقوفه |
| رئيس البلدية | سلطته بالقيمة والأسلوب (يُنفِّذ حاليًا كل شيء بحكم الدور التقني) | نص الاختصاص والتفويض |
| القائمقام | تصديق/رقابة على قرارات البلدية وبأي سقف | نص (القانون 21/2025 غير مراجَع) |
| المحافظ | تصديق/رقابة بأي سقف | نص (القانون 21/2025 غير مراجَع) |
| ديوان المحاسبة والرقابة المسبقة | خضوع البلدية للرقابة المسبقة/اللاحقة وسقفها (بند 9 في المراجعات المعلّقة) | نص وتحديد الخضوع |
| وحدة الشراء في البلدية | وجودها وتشكيلها وتفويضاتها (الملف القانوني للبلدية غير مُدخَل) | نظام البلدية الداخلي/قرارات التشكيل |
| لجنة التلزيم/الاستلام/الفتح | التشكيل والنصاب والمهام؛ النظام يسجّلها دون التحقق من تشكيلها | نص التشكيل والتصاريح |
| هيئة الشراء العام (PPA) | دورها في الإعلان والمراجعة؛ المصادر مسجَّلة وصفيًا | نص الاختصاص |
| المدقق / مفتش مالي / مراقب عقد النفقة | غير مُمثَّل كدور؛ ملف التدقيق (Audit Pack) للرئيس/المسؤول فقط | تعريف الدور وصلاحياته |
| عضو لجنة (دور فردي) | لا حساب ولا دور؛ الأعضاء أسماء نصية | تعريف الأدوار وفصل المهام |
| فصل المهام (إدخال/مراجعة/اعتماد/صرف) | لا فصل: المستخدم نفسه يُدخل ويراجع ويلتزم ويدفع (انظر `PERMISSION_MATRIX.md`) | سياسة الفصل المطلوبة قانونيًا |

## 5) ملخص الفجوات

1. كل الكتابة تمرّ بدورين فقط (رئيس/مسؤول) دون تمييز؛ لا موظف شراء ولا لجنة ولا مدقق.
2. لا نموذج لسقوف الاختصاص والتصديق والرقابة: النوع موجود في الجدول (0040) لكن لا RPC ولا محرك ولا واجهة (انظر `PROCUREMENT_THRESHOLDS_REGISTRY.md`).
3. عدم فصل مُدخِل السقف عن مراجعه، وعدم تسجيل المراجع.
4. F-3: الرئيس التجريبي قد يكتب على بلدية حقيقية (قرار معلّق، مسّ كل الوحدات).
5. 0043–0046 مسودات غير مطبقة؛ تشمل تقوية الختم (F-1) وتضييق قراءة المصادر (F-2).
6. محاولات الرفض غير مسجّلة في التدقيق؛ ومن هو رئيس في بلديتين يعمل دائمًا على الأولى.
7. المساعد الذكي وحقن التعليمات لم تُختبر؛ والتدقيق الأمني لم يقارن الصلاحيات الحيّة (`pg_policies`) كاملة، بل جرى فحص حيّ جزئي هنا للدوال الثلاث فقط.
