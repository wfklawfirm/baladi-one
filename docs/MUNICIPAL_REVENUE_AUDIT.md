# تدقيق الإيرادات والتحصيل البلدي — BALADI ONE (25/11/2026)

> تدقيق هيكلي وليس رأيًا قانونيًا. لا يحتوي النظام ولا هذا التقرير على أي نسبة رسم أو غرامة أو إعفاء أو رقم مادة غير متحقَّق منه؛ كل ما يتعلق بالأساس القانوني للجباية **يلزم تحقق** من النصوص الرسمية (انظر LEGAL_AUDIT.md و FINANCIAL_WORKFLOW_AUDIT.md: لم يُراجَع بعد الأساس القانوني للرسوم ولا النظام المالي المنطبق).

## 1) ما هو موجود قبل هذا العمل (وحدة التحصيل: 0014 + 0016)
| البند | الواقع | التصنيف |
|---|---|---|
| تسجيل إيصال تحصيل (`record_collection`) | مبلغ/عملة/طريقة/رقم إيصال نصي حرّ، يكتب `collection_entry` ويدوّن audit | PARTIALLY IMPLEMENTED |
| ترقيم الإيصالات | `receipt_no` نص اختياري لا فريد ولا متسلسل ولا بسلسلة؛ يمكن تكراره أو تركه فارغًا | MISSING + DATA INTEGRITY RISK |
| منع تكرار التحصيل | `record_collection` بلا أي حماية (لا مفتاح تكرار، لا ربط بمستحق): نقرتان = تحصيلان | DATA INTEGRITY RISK |
| `receivable_settle` | يمنع تجاوز المتبقي ويدعم الجزئي؛ لا مفتاح تكرار؛ رقم الإيصال حرّ | PARTIALLY IMPLEMENTED |
| إلغاء/تصحيح إيصال | غير موجود؛ لا حذف أيضًا (لا سياسة)، لكن لا آلية موثَّقة للعكس | MISSING |
| سجل المكلّفين | غير موجود (`payer_ref` رمز نصي في المستحق فقط) | MISSING |
| التكليف (تقدير الرسم) والربط بقرار بلدي | غير موجود؛ المستحق يُدخل يدويًا بلا قرار ولا أساس ولا سنة | MISSING |
| دورة أمر القبض/التبليغ/الاعتراض/التصحيح | غير موجودة | MISSING |
| سجل قواعد الرسوم (صك، مادة، معدل، إعفاءات، غرامات، فترة سريان) | غير موجود | MISSING |
| الإعفاءات الموثَّقة | غير موجودة | MISSING |
| المتأخرات | `arrears()` في finance: مجموع المتأخر بالعملة بلا تقادم ولا غرامة | PARTIALLY IMPLEMENTED |
| مطابقة الصندوق اليومية | غير موجودة | MISSING |
| الصلاحيات والفصل بين المهام | `record_collection` متاح لأي موظف؛ لا دور «أمين صندوق» منفصل ولا فصل بين من يكلّف ويقبض ويلغي | SECURITY RISK (فصل المهام) |
| RLS والقراءة | قراءة موظفي البلدية مع قاعدة العرض التجريبي؛ لا كتابة مباشرة | LEGALLY UNVERIFIED (بنيويًا سليم) |
| تعدد العملات | العملات لا تُجمع؛ سعر الصرف غير مُدار | PARTIALLY IMPLEMENTED |
| `collection_entry.amount > 0` | يمنع القيود المعاكسة، فلا طريقة لعكس إيصال دون حذف | INCORRECT (لعكس موثَّق) |
| الصحة القانونية لأي رسم/نسبة | لا شيء مُحمَّل | LEGALLY VERIFIED: لا شيء |

## 2) ما أضافته الوحدة الجديدة (الترحيل 0022 — **كُتب ولم يُطبَّق**)
| البند | التنفيذ | التصنيف |
|---|---|---|
| سجل المكلّفين | `revenue_taxpayer`، رمز مرجعي فريد لكل بلدية، الاسم اختياري، يمنع الأرقام الشبيهة بالهاتف | IMPLEMENTED BUT LEGALLY UNVERIFIED (تصنيف المكلّف وبياناته المطلوبة قانونًا) |
| سجل قواعد الإيراد | `revenue_rule` فارغ، حالة المراجعة الافتراضية `pending_review`، فترة سريان `effective_from/to`؛ لا بذور | IMPLEMENTED (المحتوى القانوني: MISSING عمدًا) |
| اختيار المعدل بفترة سنة التكليف | `_rev_pick_rule` (وانعكاسه `pickRule` في TS): قاعدة **متحقَّق منها** واحدة تتقاطع مع السنة؛ صفر أو أكثر من واحدة = لا احتساب. لا يُستعمل تاريخ اليوم | IMPLEMENTED (اختبار وحدة) |
| التكليف | `revenue_assess`: مكلّف، رسم، سنة، أساس، مبلغ يدوي، استحقاق، قرار بلدي اختياري (يُحذَّر من غيابه)، مبلغ مرجعي من قاعدة متحقَّق منها للمقارنة فقط، منع تكرار (مكلّف+رسم+سنة+مرجع موضوع) | IMPLEMENTED BUT LEGALLY UNVERIFIED |
| الإعفاءات | `revenue_exemption`: لا إعفاء بلا قرار أو مستند، يمرّ بمراجعة (مراجعة/اعتماد/سحب بسبب)، والإعفاء المعتمد يمنع التكليف. إعفاء كلي فقط؛ الجزئي يمرّ عبر الاعتراض والتصحيح | IMPLEMENTED BUT LEGALLY UNVERIFIED |
| أمر القبض | `revenue_order_issue`: أمر فعّال واحد لكل تكليف، ترقيم (سنة/تسلسل)، وينشئ `receivable` مرتبطًا فتبقى لوحات المالية والمتأخرات متسقة | IMPLEMENTED BUT LEGALLY UNVERIFIED (من يصدر الأمر وصيغته) |
| التبليغ | تاريخ + طريقة + إثبات إلزامي؛ لا تُحتسب مهل قانونية | PARTIALLY IMPLEMENTED (المهل: يلزم تحقق) |
| الاعتراض والمراجعة والتصحيح | تسجيل/بتّ (قبول مع مبلغ مصحَّح، رفض، سحب)، سجل قبل/بعد، اعتراض واحد مفتوح، يوقف التحصيل | PARTIALLY IMPLEMENTED (المهلة والجهة والأثر على التحصيل: يلزم تحقق) |
| التحصيل (كامل/جزئي) | `revenue_collect`: قفل صف الأمر، يمنع تجاوز المتبقي، مفتاح تكرار إلزامي، يعيد الإيصال نفسه عند إعادة الإرسال، يكتب `collection_entry` مرتبطًا بالمستحق | IMPLEMENTED |
| ترقيم الإيصال | فريد على (بلدية، سلسلة، سنة مالية) فقط، سلسلة قابلة للضبط، **بلا قيد فريد شامل**؛ عدّاد بقفل | IMPLEMENTED BUT LEGALLY UNVERIFIED (نطاق الترقيم، السنة المالية المفترضة ميلادية) |
| إلغاء الإيصال | عكس موثَّق فقط (سبب ≥10 أحرف + مرجع مستند، رئيس/مدير): الإيصال يبقى بحالة معكوس، ويُضاف قيد سالب مرتبط `reversal_of` (قيد فريد لكل أصل)؛ حذف/تعديل الإيصال ممنوع بمشغّلات | IMPLEMENTED |
| المتأخرات | حسب العملة وأعمار (1–30، 31–90، >90)؛ الغرامة «بيانات غير متوفرة» | PARTIALLY IMPLEMENTED |
| مطابقة الصندوق | إقفال يومي لكل أمين صندوق/عملة بلقطة محفوظة، فرق + ملاحظة إلزامية، عرض الفرق بين الإيصالات ودفتر التحصيل والقيود غير المسندة، وكشف تغيّر النقد بعد الإقفال | IMPLEMENTED (الإقفال لا يُعدَّل) |
| سجل الأحداث | `revenue_event` للإضافة فقط + `audit_event` | IMPLEMENTED |

## 3) مخاطر وفجوات ما زالت قائمة
1. **SECURITY RISK — مسار موازٍ**: `record_collection` و`receivable_settle` القديمان ما زالا يعملان بلا ترقيم مسلسل ولا مفتاح تكرار، ولا يمنعان التسديد المباشر على مستحق مرتبط بأمر قبض (يتجاوز دورة الأمر/الاعتراض). المطابقة اليومية تُظهرها كـ«قيود غير مسندة إلى إيصال إيرادات». الإصلاح الكامل (إيقاف الإدخال القديم أو توجيهه) قرار تشغيلي غير مُنفَّذ هنا لعدم المساس بالصفحة القديمة.
2. **SECURITY RISK — فصل المهام**: الأدوار الحالية staff/mayor/admin فقط. التكليف والأمر والإعفاء والعكس لرئيس/مدير؛ التحصيل والإقفال لكل موظف. لا يوجد منع يمنع الشخص نفسه من التكليف والعكس. يلزم دور أمين صندوق ودور محاسب.
3. **DATA INTEGRITY RISK**: تعديل `collection_entry` مباشرة من حساب service/admin على قاعدة البيانات خارج نطاق الحماية؛ لا مشغّل يحمي ذلك الجدول القديم.
4. **DATA INTEGRITY RISK**: التحصيل بأثر رجعي مسموح حتى 31 يومًا (حد تقني اعتباطي قابل للتعديل، وليس قاعدة قانونية).
5. الترحيل يُعدّل قيد `collection_entry.amount > 0` إلى «موجب، أو سالب إذا كان عكسًا مرتبطًا»؛ أي تقرير قديم يجمع `amount` سيحصل على الصافي (مقصود)، لكن أي تقرير يعدّ الإيصالات سيعدّ القيد السالب أيضًا.
6. السنة المالية للإيصال = السنة الميلادية لتاريخ التحصيل (افتراض غير متحقَّق منه).
7. الاعتراض المفتوح يوقف التحصيل، وهو خيار حذِر وليس نصًا قانونيًا متحقَّقًا.
8. بيانات المكلّف: لا حماية خصوصية متقدمة؛ المطلوب الحد الأدنى (رمز + اسم اختياري). يلزم مراجعة قانون حماية البيانات المنطبق.
9. لا تصدير/طباعة إيصال رسمي، ولا قوالب تبليغ، ولا ربط مصرفي، ولا تحصيل إلكتروني.
10. الصفحات تتحمّل غياب الجداول: تعرض «قيد التفعيل» حتى يُطبَّق 0022.

## 4) بنود تحتاج مراجعة قانونية قبل الاستعمال الفعلي
- الأساس القانوني لكل رسم (صك، مادة، معدل، سنة سريان) وتحميله في «سجل القواعد» ثم تحويله إلى «متحقَّق منه» بملاحظة المراجع والمصدر.
- من يملك صلاحية التكليف وإصدار أمر القبض والتحصيل (رئيس البلدية، المحاسب، أمين الصندوق؟) وأوراق التوقيع.
- مهلة التبليغ والاعتراض والجهة المختصة بنظره، وأثر الاعتراض على المطالبة والتحصيل.
- الغرامات والفوائد على التأخير (لم يُحتسب شيء).
- الإعفاءات المسموحة وأساسها والجهة المخوَّلة بمنحها.
- نطاق ترقيم الإيصالات (دفتر إيصالات رسمي؟ سلسلة؟ سنة مالية؟) ومدة حفظها، وهل يُقبل الإيصال الإلكتروني.
- شروط عكس الإيصال المقبوض والاسترداد.
- سقف النقد والتحصيل بعملات أجنبية وسعر الصرف المعتمد.
